      <h3>🧩 <a href="https://github.com/vuong200514/Caeser">Caeser — Graph-based Codebase Intelligence &amp; Research Assistant</a></h3>
      <p><strong>Python · AST · Knowledge Graph · Graph-first RAG · LLM</strong></p>
      <p>A code-understanding assistant that turns a Python repository into a structured knowledge graph, then uses graph-guided retrieval to give an LLM only the code context relevant to a question. It also provides a separate research-paper Q&amp;A workflow with section-level source citations.</p>
      <ul>
        <li><strong>Static code ingestion:</strong> recursively scans Python files and parses them with Python AST without executing the analyzed project.</li>
        <li><strong>Knowledge graph construction:</strong> models <code>Module</code>, <code>Class</code>, and <code>Function</code> nodes, with <code>IMPORTS</code>, <code>DEFINES</code>, <code>CONTAINS</code>, <code>CALLS</code>, and <code>INHERITS</code> relationships. Nodes retain source code, docstrings, decorators, and line locations.</li>
        <li><strong>Cross-file resolution:</strong> resolves temporary/ghost references after project-wide extraction, assigns confidence to edges, and filters unresolved or unreliable relationships from downstream retrieval and export.</li>
        <li><strong>Graph-first two-stage retrieval:</strong> first selects up to eight relevant nodes from a compact node catalogue; then builds a focused context from source code, docstrings, and incoming/outgoing relationships. Keyword matching acts as a fallback.</li>
        <li><strong>Knowledge visualization:</strong> exports <code>graph.json</code> into an Obsidian vault, with separate Markdown pages for modules, classes, and functions connected by wikilinks.</li>
        <li><strong>Research-paper assistant:</strong> parses Markdown papers with YAML metadata and section headings, then answers questions with citations to the relevant source sections.</li>
      </ul>
      <p><strong>Evaluation on the Caeser codebase</strong></p>
      <ul>
        <li>Analyzed <strong>32 Python files</strong>, producing <strong>379 nodes</strong> (32 modules, 40 classes, 307 functions) and <strong>4,045 edges</strong>.</li>
        <li>Across a five-question evaluation, graph-first retrieval used <strong>54,682 input tokens</strong>, compared with <strong>573,712</strong> for the full-source baseline — approximately <strong>10.5× fewer input tokens</strong>.</li>
      </ul>
      <p><strong>My contributions:</strong> implemented the project scanner/ingestion pipeline and AST parser, built the Obsidian export/visualization workflow, and co-designed the graph data schema. The project report records 50% overall team contribution and 100% completion of assigned work.</p>
